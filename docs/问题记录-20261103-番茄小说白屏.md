# 番茄小说独立窗口白屏诊断

检查日期：2026-11-03。最初用户反馈 0.1.0 打开的安卓应用窗口白屏，随后授权继续修复。以下先保留初始诊断，再记录 0.1.1 的修复与验证边界。

## 初始诊断：Android 15 / API 35

- 应用：`com.dragon.read`，版本 `7.4.3.32`，versionCode `74332`，targetSdk `35`。
- 当时安装包使用的原生库 ABI：`arm64-v8a`。系统镜像为 Android 15 x86_64，配置的 native bridge 为 `libndk_translation.so`。
- 当时 Windows 管理程序、Android Emulator、scrcpy 进程仍在运行并响应；ADB 设备在线，`sys.boot_completed=1`。
- Android 记录了该应用两次 `APP CRASH(NATIVE)` 退出，信号 `SIGABRT`（6）。Android 时区为 GMT，对应北京时间 14:15:28.801 与 14:16:14.504。
- 两次崩溃均出现 `Abort message: 'Cannot process signal 11'`。
- 宿主堆栈包含 `libndk_translation.so` 的 `berberis::HandleHostSignal`；ARM 客体堆栈包含应用的 `libnpth.so`、`libmetasec_ml.so` 及 libc `memcpy`。
- 采集时 `pidof com.dragon.read` 已没有应用主进程；独立显示器仍开启，前台 Activity 为 Android 的 `SecondaryDisplayLauncher`，应用 Activity 已退出。因此窗口可以继续存在，但应用内容不再运行。

## 判断与边界

白屏对应应用原生崩溃后留下的显示窗口。当前证据将问题定位到该 APK 的 ARM64 原生代码及其在 x86_64 镜像中的转译兼容路径。尚不能只凭堆栈断定最初缺陷属于应用原生库、信号处理逻辑还是转译器；未证明改变分辨率、关闭动态缩放或重新安装应用能修复。

初始 0.1.0 宿主只在 scrcpy 启动后等待 1.2 秒并检查进程是否立即异常退出；应用稍后在 Android 内崩溃时，scrcpy 可继续运行，宿主仍显示窗口启动已完成。普通会话日志也只在界面中保留。这是当时的错误反馈和诊断缺口，已在 0.1.1 代码中补上应用状态监测、明确提示和会话日志。

## 证据

目录：`artifacts/diagnostics/white-screen-20261103-141627/`

- `exit-info.txt`：两次 `APP CRASH(NATIVE)`。
- `crash-buffer.txt`：SIGABRT、Abort message、原生和转译堆栈。
- `package.txt`：应用版本及 primaryCpuAbi。
- `processes.json`、`windows.json`：Windows 侧进程及窗口状态。
- `devices.txt`、`boot.txt`：设备在线、Android 已完成启动。
- `activities.txt`、`android-windows.txt`、`displays.txt`：应用退出后仍存在的虚拟显示器及桌面 Activity。
- `system-abis.txt`、`native-bridge.txt`、`android-timezone.txt`：系统 ABI、转译层与日志时区。

原生崩溃退出类型参考：[Android ApplicationExitInfo.REASON_CRASH_NATIVE](https://developer.android.com/reference/android/app/ApplicationExitInfo#REASON_CRASH_NATIVE)。ABI 架构说明参考：[Android ABIs](https://developer.android.com/ndk/guides/abis)。

## 0.1.1 修复与对照结果

- 在原 API 35 实例的主显示器启动，也曾产生新的原生崩溃，故障并非只发生在独立虚拟显示器中。
- 独立 API 30 对照环境出现 `Bad 'ubidi_openSized_66' call`，宿主堆栈经过 `libndk_translation.so::DoBadTrampoline`。关闭动态分辨率后仍失败，API 30 不能作为当前 APK 的可用替代。
- API 30 镜像恢复安装时曾出现安装进程重叠，导致少量官方配置文件未完整落盘。已按已校验官方 ZIP 补齐并核对镜像文件。安装脚本现在持有独占安装锁，并检查关键文件后再创建或使用 AVD。
- 独立 API 36 环境已显示番茄欢迎和个人信息说明页。用户自行点击“同意并继续”后，后台记录首页 `MainFragmentActivity` 处于 `RESUMED`、可见并完成首次绘制，当次采集没有新的应用崩溃记录。
- 首次 API 36 冷启动曾触发新监测器原先 30 秒的等待上限，尚未产生应用崩溃记录。0.1.1 将应用等待延长到 90 秒，后台 Android 启动等待仍为 4 分钟；没有强制触发 90 秒边界测试。
- 默认运行环境改为 Android 16 / API 36，AVD 为 `AndroidOnDesktop_API36`，端口为 `5584`。API 35 / 30 AVD 与数据目录保留，各自的登录、书架和缓存没有自动迁移。
- 默认使用固定 Android 分辨率，不随 Windows 窗口大小自动重建显示配置。

## 崩溃检测与错误反馈

应用启动时等待主进程以及目标显示器中的可见、已绘制 Activity。进入运行状态后继续监测新的应用退出记录，区分 Java 与原生崩溃；确认失败时关闭对应会话创建的窗口，显示错误横幅并将原因保存到 `data/logs`。原生错误会尽力附加匹配 PID、包名与时间的崩溃摘要。

在 API 30 中以番茄实际原生崩溃验证了错误横幅可见、日志落盘和原因记录，证据为 `artifacts/verification/repair/native-crash-ui-api30.json`。普通样例运行 15 秒及正常关闭未误报，证据为 `artifacts/verification/repair/healthy-session.json`。

API 36 后续证据位于 `artifacts/diagnostics/repair-20261103-142243/`，包括 `api36-after-consent-activities.txt` 和 `api36-after-consent-exit-info.txt`。0.1.1 最终构建、启动、默认环境与快捷方式核对以 `artifacts/verification/release-0.1.1/` 为准。

## 仍待验证

- 未修改番茄 APK。成熟模拟器内核的安装包已准备，但未安装或接入，不能当作已验证方案。
